Database indexes

An index gives the database a path to selected rows. That path costs storage and extra work when data changes.

About 5 minutes, with the diagram and question

A lookup needs a path to the row

A URL shortener stores a short code beside a destination URL. Each stored pair is a row in a table.

A request for /a7Kp needs the row whose short_code equals a7Kp. SQL expresses that request as a query:

SELECT long_url
FROM links
WHERE short_code = 'a7Kp';

Without a suitable index, the database can scan the table and check rows against the condition. A scan can examine many unrelated rows.

An index is an extra data structure that helps the database locate rows through selected values, such as the short code.

Like a book index, it gives a route to the relevant content. The database manages this structure alongside the table.

Source: PostgreSQL: introduction to indexes.

Where does the index act in this request?

The primary key already creates an index

A primary key uniquely identifies each row. Its value cannot be null, which means absent.

CREATE TABLE links (
  short_code TEXT PRIMARY KEY,
  long_url TEXT NOT NULL
);

PostgreSQL automatically creates a unique B-tree index for this primary key. A B-tree organizes keys in a tree for lookup.

The index supports lookup by short_code and prevents duplicate codes. No second index on that same column is necessary for this query.

The table stores the destination URL. The index in this example stores the key and information that locates the row.

Sources: PostgreSQL: unique indexes; PostgreSQL: index types and features.

The gain depends on the query

Illustrative design assumption: the table holds one million links, and each redirect needs at most one row.

This is a selective query: its condition selects a small part of the table. An index on the short code suits this access pattern.

  • Gain: the database can skip unrelated rows when it locates a specific code.
  • Lose: the index consumes storage.
  • Lose: inserts, deletes, and changes to indexed values require extra work to maintain the index.
  • Limit: this index does not provide the same lookup path for a query by long_url.

Source: PostgreSQL: indexes and their costs.

A query that needs most rows gains less from separate row lookups. A table scan can cost less, especially for a small table.

The query planner chooses how PostgreSQL executes a query. An index does not guarantee that the planner uses it.

EXPLAIN shows the selected plan without execution. A plan with Index Scan uses an index; Seq Scan reads the table sequentially.

EXPLAIN
SELECT long_url
FROM links
WHERE short_code = 'a7Kp';

Check a representative database before you claim a latency improvement. Row count alone cannot predict the response time.

Source: PostgreSQL: how to use EXPLAIN.

An index is different from a replica

Replication maintains copies of data across database servers. Those copies can support availability or distribute reads, with rules for how updates reach each copy.

An index provides an access path within a database. It does not provide a standby database if that server fails.

A replica can have indexes too. These mechanisms solve separate problems.

Source: PostgreSQL: high availability and replication.
