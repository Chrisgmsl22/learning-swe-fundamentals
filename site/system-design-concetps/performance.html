04 · Performance and capacity

How does the system handle demand?

More traffic can exhaust the CPU, memory, database, or network. Each technique changes one part of that path.

04.01

Vertical scaling

Vertical scaling gives one machine more CPU, memory, or other resources. The service still uses one machine.

  • Gain: One machine can handle more work with few application changes.
  • Limit: One machine still has a capacity limit and can fail. An upgrade can require downtime.

04.02

Horizontal scaling

Horizontal scaling adds machines that share the work. Here, both URL servers use the same database.

  • Gain: More servers can increase total request capacity and provide spare capacity after a server failure.
  • Limit: The database can remain the bottleneck. Shared state and coordination add work. Two servers do not guarantee twice the capacity.

04.03

Load balancers

A load balancer selects a server for each request. Health checks help it exclude servers that fail those checks.

  • Gain: Traffic can move away from an unhealthy server.
  • Limit: Health checks can miss some faults. The load balancer also needs a failure plan; it does not repair the application.

04.04

Caching

A cache holds a reusable copy. In this cache-aside example, the URL retriever owns the cache lookup and database fallback.

  • Gain: Repeated reads can avoid database work and reduce response time.
  • Limit: A cached URL can become stale. The cache adds little value when requests rarely reuse data.

04.05

CDN

A content delivery network (CDN) serves cached content from locations near users. An origin server supplies the original content.

  • Gain: Nearby copies can reduce network travel and origin traffic.
  • Limit: Copies need expiry or invalidation rules. Personalized or frequently changed responses need careful cache rules.

AWS: CloudFront request flow · Mermaid source

04.06

Message queues

A message queue holds work until a consumer can process it. The producer and consumer do not need to act at the same time.

  • Gain: A queue can absorb short bursts and move optional work outside the request path.
  • Limit: A growing backlog increases delay. Delivery rules can permit duplicates, so the consumer must prevent duplicate effects where necessary.
