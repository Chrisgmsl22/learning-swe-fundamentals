Request flow

How does a request reach the right code?

01.01

Client-server

A client asks for work. A server accepts the request and returns a result.

  • Gain: The server keeps shared rules and data in one place.
  • Limit: The client needs a reachable server for this request.

01.02

IP

The Internet Protocol uses addresses to route packets between networks. A packet is a small unit of data.

  • Gain: Addresses let networks direct packets to their destinations.
  • Limit: IP alone does not guarantee delivery or identify the correct application.

MDN: Internet and IP addresses · Mermaid source

01.03

DNS

The Domain Name System resolves a name such as short.example to records, which can include a server address.

  • Gain: A stable name can refer to a different address after an infrastructure change.
  • Limit: Cached answers can delay an address change. DNS does not forward the HTTP request.

MDN: Names and addresses · Mermaid source

01.04

Proxy / reverse proxy

A forward proxy acts for clients. A reverse proxy accepts requests for servers and sends each request to a suitable server.

  • Gain: Proxies provide a common point for access rules and traffic control.
  • Limit: Each proxy adds work and another possible failure point.

MDN: Proxy servers · Mermaid source

01.05

Latency

Request latency is the elapsed time from a client request to its response. Network travel, queues, and computation all contribute.

  • Gain: A measurement for each step shows where a delay occurs.
  • Limit: A faster database cannot remove network delay. Averages can hide slow requests.

MDN: Latency · Mermaid source

01.06

HTTP/HTTPS

HTTP defines web requests and responses. HTTPS protects HTTP data in transit with TLS, a protocol for secure connections.

  • Gain: HTTPS protects data in transit and helps the browser verify the server identity.
  • Limit: HTTPS does not decide which users may access a record or whether a destination is safe.
