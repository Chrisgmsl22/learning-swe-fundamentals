System design — the weekly cycle

One design a week is the usual pace. Monday and Wednesday are usual 45-minute sessions. Friday is optional; resume unfinished work within the scheduled slots.

  1. Mon 20:00–20:45 — Attempt. Use one question at a time. State assumptions and draw your own design.→ attempt.md + sketch
  2. Wed 20:00–20:45 — Check. Explain your intent, then compare choices. Run the 3×3 sweep. Record open questions.→ gaps.md
  3. Fri 18:00–18:45 — Optional. Close one gap, or every third Friday revisit an older design if attending.→ a note or revisit record

Every third Friday, if attending, replace gap closure with a revisit in the same slot. No extra session. See REVIEW-QUEUE.md.

LLD — the weekly cycle

One pattern a week. Every ~4 weeks, one full problem combining several.

  1. Tue — Study one pattern. What problem it solves, and what it costs.
  2. Thu — Bound one finishable behavior for Sunday's build.
  3. Sun — Build a small problem in Python, by hand, 60–90 minutes.

On Sunday, build by hand the one finishable behavior you selected on Thursday. The Fast Expense Tracker is a separate personal project around 21:00 Friday; its duration is not set. AI integration is a learning direction, not a required feature.

The rules

  1. End each session with an artifact or an update. Short videos, explanations, and small examples can help. Then apply the concept yourself.
  2. Saturday is off. Dinner stays 19:00–20:00.
  3. Do not add work to compensate for an unfinished stage. AI practice during work hours adds no evening quota.
  4. Use real questions to select concepts. The gap list guides depth. The topic map records evidence.
  5. Keep your own attempt before the full reference solution. Strict silent or timed simulation requires an explicit request.
