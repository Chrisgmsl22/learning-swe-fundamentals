# System design

Use guided practice to build designs you can explain.
The [schedule](../SCHEDULE.md) supplies three weekly slots, with one design per week as the usual pace.
Carry unfinished work forward within those slots.

## Start or resume

1. Read [PROGRESS.md](../PROGRESS.md) for the current exercise, stage, and next action.
2. Open the current prompt and existing attempt.
3. Use the [framework](FRAMEWORK.md) for one question at a time.
4. Record the next action when the session ends.

For a new exercise, start with its requirements. For an existing exercise, ask about one request in the sketch.
Use PROGRESS.md for the current exercise and stage.
A reference file does not prove that the learner completed evaluation.

| `concepts/` | Notes that record the learner's application of a concept |

Attempt, evaluation, and gap closure are stages, independent of the weekday.
Use short videos, explanations, or small examples before application when useful.
Preserve your own attempt before the full reference solution for that exercise.
Strict silent or timed simulation requires an explicit request. Ask about time only for an explicit timed session.

The shared [mentor brief](../CLAUDE.md) and repo files preserve context for Codex and Claude.
They provide the same instructions and saved state, but cannot guarantee identical responses.
