# System design

One design a week, across three sessions. See `../SCHEDULE.md` for the slots and
`FRAMEWORK.md` for the method, the 3×3 sweep, and the coverage map.

```
FRAMEWORK.md          the method, the checklist, the coverage map
REVIEW-QUEUE.md       spaced repetition for designs
concepts/             one note per concept, written when a gap demanded it
problems/NN-name/
  PROBLEM.md          the prompt and constraints
  attempt.md          your reasoning, written BEFORE you look at anything
  attempt.png         your sketch
  reference.md        the worked version — written only after yours exists
  gaps.md             what you could not answer  <- this is the curriculum
```

## The loop

| Day | Session | Artifact |
| --- | --- | --- |
| **Mon** | Attempt, timed and blind | `attempt.md` + sketch |
| **Wed** | Check against the reference, run the 3×3 sweep | `gaps.md` |
| **Fri** | Close one gap properly, with a diagram | a note in `concepts/` |

**Every third Friday**, re-draw an old design blind instead. See `REVIEW-QUEUE.md`.

## The one rule

**Never open `reference.md` before `attempt.md` exists.** Reading a good design feels like
learning and is not. The gap between your version and the reference is the entire lesson.
