# URL shortener: codes, collisions, and public links

The learner resumed after a break. Duration was not measured. This was the agreed bounded wrap-up, not a complete design evaluation.

## Learner reasoning

- Proposed generating a code, checking whether it exists, and retrying if necessary before storing the mapping. Called this memoization.
- Worried about lookup time with 100 million rows and suggested NoSQL would be faster than a relational database.
- Identified the concurrent check-and-write problem as a race condition. Suggested a queue to serialize requests and asked whether that was excessive.
- Recognized that the code is a public tiny ID; confirmed the example with a separate internal ID, short code, and destination URL.
- Identified guessing other people's short links as a security concern, including when the code and internal ID are the same.
- Chose public redirects: anyone with a link can use it. The destination service owns its login requirements.

## Mentor explanations

- Memoization caches computation results. Checking whether a generated code already exists is a uniqueness check.
- Indexed SQL lookups do not require scanning every row. Database family alone does not determine lookup speed.
- A unique constraint prevents two concurrent inserts from claiming the same code. The losing request can generate another candidate and retry, with a retry limit.
- One queue consumer could serialize requests but adds ordering and job-processing machinery that this case does not require.
- A separate internal ID is optional; the short code could be the primary key.
- A redirect returns the destination in the Location header; the browser requests that destination separately.
- Random codes with a sufficiently large space reduce guessing but do not provide authorization. Knowing an internal ID must not grant permission.

These mechanisms and tradeoffs were mentor explanations. The learner has not independently implemented or justified the unique-constraint strategy, code length, retry limit, or an indexed schema.
